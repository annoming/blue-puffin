## 5. 交互与数据规则

1. **生成时机**：建档完成且首次同步后自动生成；之后每周一 00:00 生成下一周；失败不覆盖上一周。
2. **重新生成**：确认后按钮 loading，成功后回到本周顶部并 toast「计划已更新」；失败保留旧计划 + danger banner。
3. **计划只读**：本迭代不支持拖动/编辑/跳过；不设计未排期的「AI 调整」入口。
4. **完成判定**：仅当跑步记录关联该任务且距离 ≥ 目标 80%（或时长 ≥ 目标 80%）才标记完成；否则标记「部分完成」（周视图显示 `check_circle` 描边 + 目标文字 `text/secondary`，详情显示「完成度 65%」进度条）。
5. 部分完成状态必须有设计：周视图右侧为 `check_circle_outline` 20 `warning`，点击进入详情看到完成度条（高 6，`warning`，标签「完成度 65% · 6.4 / 10 km」）。
6. 训练类型映射与 `weekly_plan.dart` 一致：`easy/tempo/long_run/interval/rest`；未知类型降级为「训练」+ `rest` 灰。

## 6. Flutter 实现要点

| 模块 | 建议 |
|---|---|
| 周视图 | `PageView` + 7 日列表；每周数据按 `weekNumber` 缓存；`intl` 格式化「10月27日 - 11月2日」 |
| 今日卡 | 独立 `TodayTaskCard` widget，传入 `TrainingTask` + `weekNumber` + `dayOfWeek` + 完成态枚举；明天任务不在本卡展示 |
| 状态条 | 用 `Container(width: 3)` + `decoration`，避免 `Card` 默认 margin 造成对齐偏差 |
| 生成计划 | Riverpod `FutureProvider.family` 按周；失败 `AsyncError` 渲染错误态；重新生成 `ref.invalidate` |
| 跟随刷新 | 结果页保存后 `ref.invalidate(trainingTasksProvider)` 与 `weeklyPlanProvider` |
| 文案 | 计划说明中的跑量/目标从建档读取，不写死；无目标时省略对应短语 |

验收：四个页面状态齐全；休息日、部分完成、空/错/载均有稿；周切换不越界；完成后三处状态同步；不出现本迭代外的编辑/AI 调整入口。
