# 03 · 交互流程与状态说明（Interaction Flows）

覆盖：页面跳转、返回、跑步中断与恢复、权限、GPS 弱信号、后台运行、加载/空/错误态。
路由路径与现有 `lib/core/routing/app_router.dart` 对齐，新增路由标注为「新增」。

---

## 1. 信息架构与导航

```
底部导航（4 tab）
├── 首页 /                        首页概览：今日任务卡、本周进度、开始跑步
├── 训练 /training/plan          周训练计划（周视图）
│    ├── /training/today         今日训练（从首页卡片进入，也可直达）
│    ├── /training/task/:taskId  训练任务详情
│    └── /run?taskId=xxx         从任务开始跑步（全屏）
├── 记录 /run/history            历史跑步记录列表
│    └── /run/result/:runId      跑步结果详情（新增）
└── 我的 /profile/me             我的：用户信息、Coros 绑定、设置入口
     ├── /profile                 建档信息（编辑）
     ├── /user/:userId            个人信息详情（现有）
     ├── /sync/coros              Coros 绑定与同步
     └── /run/history             历史记录（与 tab 复用）
```

跑步流程（全屏，无底部导航）：

```
首页「开始跑步」 / 任务详情「开始跑步」
   → 跑步页 · 空闲（地图预览 + 上次成绩）
   → 点击开始 → 定位中（权限检查）
        ├── 权限拒绝 → 权限说明弹层 → 去设置 / 暂不（返回空闲）
        └── 定位成功 → 跑步中
              ├── 暂停 → 暂停态（数字降饱和，地图仍跟随）
              ├── 切后台/来电 → 自动暂停 + 本地计时保护 → 回前台恢复
              ├── 结束（长按）→ 结束确认弹层 → 结果页
              └── 放弃 → 放弃确认 → 返回来源页
   → 结果页（保存成功 / 待同步）→ 分享卡片 / 返回首页
```

### 1.1 跳转与返回规则

| 动作 | 行为 |
|---|---|
| 底部 tab 切换 | 保留各 tab 栈顶；再次点击当前 tab 回到栈顶 |
| 列表 → 详情 | push 右进（260ms）；顶部返回 / iOS 边缘右滑返回 |
| 跑步页 push | 从下往上（300ms，`easeOutCubic`），返回需二次确认（见 §3.4） |
| 结果页 push | 替换跑步页（`replace`），返回直接回来源页（首页/任务详情），不回到跑步中 |
| 结果页 → 分享 | 底部弹层；关闭后停留结果页 |
| 授权外部浏览器（Coros OAuth） | 系统浏览器/内置 WebView 打开；回调后回到 Coros 页并刷新状态 |
| 权限「去设置」 | 跳系统设置；返回 App 时重新检查权限并自动继续原流程 |

- 所有页面返回手势不得丢失未保存数据：结束确认弹层打开时，Android 返回键 = 关闭弹层。
- 跑步中按系统返回 = 打开「结束本次跑步？」确认，不直接退出。

## 2. 跑步生命周期状态机

| 状态 | 触发 | 界面表现 | 数据行为 |
|---|---|---|---|
| `idle` | 进入跑步页 | 地图预览（当前位置）、上次成绩卡、开始按钮 | 不采集 GPS |
| `acquiring` | 点击开始且权限已授予 | 地图中心脉冲点、「正在定位…」+ 信号格、开始按钮变「取消」 | 订阅定位，等待 accuracy ≤ 30m 的首个点 |
| `running` | 首个有效点到达 | 恒暗运动模式，里程/时长/配速实时更新，「暂停 / 结束」 | 每秒计时；每 3s 或移动 5m 记录轨迹点；写本地草稿 |
| `paused` | 点击暂停 / 自动暂停 | 数字降为 60% 饱和并显示「已暂停」，主控变「继续」，结束仍可长按 | 停止计时，保留轨迹；继续后从暂停点接续（不计暂停时长） |
| `resuming` | 点击继续 | 按钮 loading 180ms，等待 GPS 定位恢复 | 重新订阅定位；首个点到达后回到 `running` |
| `ending` | 长按结束且确认 | 结果页加载态（保存中） | 停止采集，结束时间落库，关联 task |
| `saved` | 保存成功 | 结果页完整数据 | 记录可分享/可查看 |
| `saveFailed` | 保存失败 | 结果页顶部 `danger` banner「记录已暂存在本地，联网后自动同步」+ 重试 | 本地草稿保留，标记 `pending` |

### 2.1 定位中细节

- 最多等待 **30 秒**：超时后显示 `warning` banner「定位信号较弱，建议到开阔地带」，主按钮变「仍然开始」（允许低精度开始），次按钮「取消」。
- 信号格：4 格，accuracy > 50m 1 格（`run/gpsLost` 文案「信号弱」），30–50m 2 格（warning），15–30m 3 格，< 15m 4 格（success）。
- 定位中不做倒计时，不强制开始。

### 2.2 跑步中

- 主数字：里程（`display/xl` 64）居中；次行 时长（22/600）+ 配速（22/600），配速标签「当前配速」；右侧小字「平均配速」。
- 屏幕常亮（`wakelock`），锁屏按钮可临时锁屏（仅显示「长按解锁」）。
- 每公里触发一次触觉轻震 + 顶部 1.5s 轻提示「第 3 公里 · 6'02"」。
- 轨迹自动跟随，用户拖动地图后 5s 无操作恢复跟随，并显示「回到当前位置」按钮。

### 2.3 后台运行 / 来电

- 进入后台：启动前台服务通知「步凡正在记录跑步 · 6.42 公里」，通知含「暂停」「结束」动作（Android）；iOS 显示实时活动/常驻通知（若系统支持），否则进入后台即自动暂停并提示。
- **Android**：后台继续采集，回前台显示「已回到跑步」toast；超过 5 分钟无位移未暂停则弹「是否暂停？」。
- **iOS**：允许后台定位，但来电/其它 App 占用时自动暂停；回到前台顶部 banner「已自动暂停 · 来电期间未计时」，提供「继续」。
- 来电：`phone_state` 变化即自动暂停（`paused` + `autoPaused=true`），挂断后**不自动恢复**，避免用户未准备好直接跑；显示「继续跑步」主控。
- 进程被杀后重进：读本地草稿 → 跑步页弹层「检测到未结束的跑步（10/28 07:12 开始，已跑 6.42 公里）」。
  - 草稿 ≤ 24h：按钮「继续记录」/「保存并结束」/「放弃记录」。
  - 草稿 > 24h：只提供「保存并结束」/「放弃记录」，并说明「超过 24 小时的记录无法继续，但可以保存已完成的数据」；不显示「继续记录」。详见 `screens/01-run-home.md §7.3`。

### 2.4 结束与放弃

- 结束必须长按 800ms，避免误触；松手前可取消。
- 确认弹层只在「已跑 > 0.1km 或 > 30s」时出现；否则直接放弃并 toast「跑步时间太短，未保存」。
- 结束保存后：若来自训练任务，结果页顶部显示「已关联今日训练 · 轻松跑」；未关联时显示「关联到今日训练？」操作（可一键关联，仅当天有计划时出现）。

## 3. 权限流程

| 权限 | 触发时机 | 文案 | 拒绝后 |
|---|---|---|---|
| 定位（使用期间） | 首次点开始跑步 | 「步凡需要定位权限来记录轨迹、距离和配速」 | 弹层「需要定位权限」+ 去设置 / 暂不；返回空闲态，不可开始 |
| 后台定位 | 首次开始跑步前（Android 10+ / iOS Always） | 「允许后台定位，锁屏或切到其它 App 时也能持续记录」 | 允许仅前台运行：跑步中切后台显示 banner「后台记录未开启，切到后台可能中断记录」 |
| 通知 | 首次开始跑步（Android 前台服务需要） | 系统弹窗，无自定义文案 | 不阻塞；后台通知不可见时跑步页提示「通知已关闭，后台记录状态不可见」 |
| 运动/健康数据 | 本迭代不采集心率，不申请 | — | — |

- 权限拒绝属于**可恢复状态**：任何时候从系统设置返回，重新进入跑步页会重新检查，不要求重启 App。
- 不在启动时批量索要权限；只在用户点击「开始跑步」时申请。
- 拒绝弹层必须给出「去设置」，不能只 toast。

## 4. GPS 弱信号 / 丢失

| 状态 | 判定 | 界面 |
|---|---|---|
| 信号弱 | 最近 10s accuracy > 30m | 跑步中顶部 `warning` banner「GPS 信号弱，轨迹可能有偏差」+ 信号 2 格；banner 不遮挡数字 |
| 信号丢失 | 15s 无有效点 | banner 升级 `danger`「GPS 信号丢失，正在重新定位…」+ 脉冲图标；计时继续，里程暂时冻结并显示「—」直到恢复 |
| 恢复 | 收到 accuracy ≤ 30m 点 | banner 变为 `success`「GPS 已恢复」2s 后消失 |

- 弱信号/丢失**不自动暂停**（用户仍在跑），只在结果页标注「本次轨迹有 2 处信号缺失」。
- 轨迹缺口用虚线连接（结果页），并在轨迹图右下角显示「信号缺失」图例。

## 5. 训练计划流程

```
首页今日卡 → 任务详情 → 开始跑步 → 结果页（自动关联）
     │                        └→ 返回首页：今日卡变「已完成」，周进度 +1
     └→ 查看本周 → 周视图 → 切换周（上一周/下一周）
周一 00:00 生成新一周计划（规则版）
```

- 计划生成：建档完成 + 拉取历史数据后自动生成；生成中周视图骨架屏；失败显示错误态 +「重新生成」。
- 今日无任务（休息日）：首页显示休息日卡；任务详情按钮为「查看本周计划」。
- 已完成任务：详情页按钮「已完成」禁用，显示完成时间与关联跑步记录入口。
- 周视图支持左右滑动切换周，最多可看前 4 周/后 4 周；本周以外为只读。
- 计划调整（重新生成）本迭代只提供「重新生成」入口，不支持手动编辑。

## 6. Coros 绑定与同步流程

```
我的 → Coros 卡片（未绑定）→ Coros 页 → 授权
  → 系统浏览器 OAuth → 回调 success → 显示「已连接」+ 立即同步
  → 回调失败/取消 → 回到 Coros 页，danger banner「授权失败」+ 重试
已连接 → 手动同步 / 自动同步（打开 App 时，>= 6h 间隔）
同步中 → 进度文案（拉取第 2 页…）→ 成功（新增 3 条）/ 部分成功（2 条失败）/ 失败
```

- 授权中：按钮「授权中…」+ 16pt 指示器，禁止重复点击；超时 60s 报错。
- 授权失败分类文案：网络问题 / 用户取消 / 账号密码错误 / 服务暂不可用；均提供「重试」与「联系支持」（Text）。
- 同步失败不阻塞 App：保留上次成功时间，显示「上次同步 10/28 07:10」。
- 解除绑定：危险弹层二次确认，保留已同步记录。
- 未绑定状态在「我的」显示「未绑定」+「去绑定」；首页今日卡若计划基于空数据生成，显示 info「完善 Coros 数据后计划会更准确」（仅一次，可关闭）。

## 7. 全局状态矩阵（每页必须实现的态）

| 页面 | 加载 | 空 | 错误 | 离线 | 权限 |
|---|---|---|---|---|---|
| 首页 | 骨架（任务卡 + 周进度） | 无计划：引导生成 | 加载失败 banner + 重试 | 顶部离线 banner | — |
| 跑步页 | 定位中（非骨架） | — | 定位失败 → 权限/信号引导 | 离线不阻塞（本地记录） | 定位/后台/通知 |
| 结果页 | 保存中（按钮 + 骨架数字） | 距离 < 0.1km → 不生成结果 | 保存失败 banner + 重试 | 待同步 pill | — |
| 周视图 | 骨架（7 行） | 无计划 → 生成引导 | 错误态 + 重新生成 | 顶部离线 banner | — |
| 任务详情 | 骨架（标题 + 数据） | 任务不存在 → 空态 + 返回计划 | 错误态 + 重试 | — | — |
| 历史列表 | 3 行骨架 | 空态（开始跑步） | 错误态 + 重试 | 离线 banner + 本地记录 | — |
| 我的 | 骨架（头像 + 两卡） | 未建档 → 完善建档入口 | 错误态 + 重试 | 离线 banner | — |
| Coros 页 | 状态加载骨架 | 未绑定 → 授权引导 | 授权/同步失败 banner | 离线 banner + 禁用同步 | — |

- 骨架与内容切换不做淡入超过 200ms，避免闪烁。
- 任何错误都提供「重试」，除权限/授权类提供「去设置」。

## 8. 反馈与文案

| 场景 | 反馈 | 文案 |
|---|---|---|
| 开始跑步 | 触觉 + 按钮态切换 | — |
| 暂停/继续 | 触觉 + 数字透明度 | 「已暂停」/「继续跑步」 |
| 每公里 | 轻震 + 顶部轻提示 1.5s | 「第 3 公里 · 6'02"」 |
| 保存成功 | 结果页进入 | 「完成！本次跑步已保存」 |
| 保存失败 | banner（不弹窗） | 「记录已暂存在本地，联网后自动同步」 |
| 同步成功 | 行内状态 + 触觉 | 「已同步 3 条新记录」 |
| 授权失败 | banner | 「Coros 授权失败，请重试」 |
| 删除/解除绑定 | 危险弹层 | 见 02 §8 |

- 禁止用全屏遮罩 loading 处理可并行的操作（如下拉刷新）。
- Toast/SnackBar 只用于一次性确认，不作为错误主载体；错误必须留在页面内可重试。
- 所有文案避免感叹号堆叠，语气专业、简短；不使用「亲」「小主」等称呼。
