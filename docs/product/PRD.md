# AI 跑步助手 PRD

## 1. 概述

AI 跑步助手是一款面向马拉松爱好者的智能跑步应用，核心定位是「个性化 AI 跑步伙伴」。它不仅能提供专业的训练计划和指导，还能像真实跑友一样与用户交流、互动、复盘和分享，真正做到既懂训练也懂陪伴。

## 2. 目标

- **核心目标**：为马拉松爱好者提供专业、个性化的训练指导，帮助用户科学备赛并提升跑步体验
- **产品目标**：打造一个既有专业性又有陪伴感的 AI 跑步伙伴，让跑步不再孤单
- **成功指标**：以日活（DAU）作为核心衡量指标

## 3. 用户画像

### 主要用户：马拉松爱好者
- **特征**：有马拉松目标（首马、破PB、挑战全程等），对训练有一定认知但需要科学指导
- **需求**：个性化训练计划、科学营养建议、训练复盘、跑步陪伴、备赛社交
- **痛点**：
  - 缺乏专业的个性化训练计划
  - 不知道如何配合训练强度调整营养
  - 跑步训练枯燥缺乏动力
  - 备赛期间孤单缺乏陪伴和交流
  - 训练数据分散在不同平台难以整合分析

## 4. 核心功能

### 4.1 MVP 核心（优先级最高）
| 功能 | 描述 | 优先级 |
|---|---|---|
| **跑步记录与同步** | 支持跑步功能，能记录跑步数据并同步跑步手表历史训练数据 | P0 |
| **个性化训练指导** | 基于用户当前跑量、目标完赛时间、可训练时间、伤病史生成并动态调整训练计划 | P0 |
| **训练计划执行** | 根据训练计划引导用户跑步，提供跑步中的指导和建议 | P0 |

### 4.2 后续核心功能
| 功能 | 描述 | 优先级 |
|---|---|---|
| **AI 跑步伙伴（人设进化）** | AI 人设根据用户性格自动演化，既能提供专业训练意见，也能分享训练心得，营造朋友式陪伴感 | P1 |
| **AI 陪跑与虚拟赛事** | 提供 AI 陪跑、实时反馈、赛前指导等虚拟赛事体验 | P1 |
| **周期性营养建议** | 根据训练强度提供周期性营养方案，需考虑过敏、饮食偏好等限制 | P1 |
| **智能社交（AI 驱动）** | AI 跑步伙伴在跑圈中自动交流互动，根据用户每次训练完成情况作复盘分析，自动发动态，AI 之间也能自主活动 | P1 |
| **训练复盘分析** | 每次训练后 AI 自动复盘，分析表现、给出改进建议并分享心得 | P1 |

## 5. 用户流程

### 5.1 首次使用流程
1. **注册登录**：用户注册账号
2. **基础信息收集**：填写跑步基础信息（当前跑量、目标完赛时间、可训练时间、伤病史、饮食偏好、过敏史等）
3. **数据同步授权**：授权同步跑步手表历史数据（优先支持 Coros，后续扩展 Garmin、Apple Watch、Polar）
4. **AI 伙伴初始化**：系统根据用户信息初始化 AI 跑步伙伴，初始人设根据用户性格预设并开始演化
5. **生成训练计划**：基于用户信息和历史数据生成个性化训练计划

### 5.2 日常使用流程
1. **查看训练计划**：用户查看当日训练任务
2. **AI 陪跑/跑步**：按计划跑步，可启用 AI 陪跑获得实时反馈和鼓励
3. **训练完成**：跑步结束后自动记录数据
4. **AI 复盘**：AI 自动分析本次训练，生成复盘报告并在跑圈发动态
5. **社交互动**：AI 伙伴在跑圈中主动交流，或用户与其他 AI/用户互动
6. **营养建议**：根据训练强度获取当日/周期性营养建议

## 6. 技术需求

| 需求项 | 描述 |
|---|---|
| **跨平台支持** | iOS 和 Android 双平台原生或跨平台开发 |
| **手表数据接入** | 优先接入 Coros API，其次 Garmin、Apple Watch（HealthKit）、Polar 等，需支持历史数据同步 |
| **AI 能力** | 大模型支持 AI 人设演化、个性化对话、训练计划生成、复盘分析、营养建议等 |
| **跑步核心** | GPS 跑步记录、配速、里程、心率、步频等基础跑步数据采集和展示 |
| **社交系统** | 跑圈动态、AI 自动发文、AI 间互动、评论、点赞等 |
| **个性化引擎** | 基于用户跑量、目标、可用时间、伤病史等因素的训练计划生成和动态调整算法 |
| **营养建议引擎** | 结合训练强度、周期（基础期/强度期/减量期等）、过敏和饮食偏好生成营养方案 |
| **数据存储** | 用户训练数据、AI 对话历史、人设演化数据、安全存储 |

## 7. 非功能需求

| 需求项 | 描述 |
|---|---|
| **性能** | 跑步记录需低功耗、GPS 定位稳定，AI 响应延迟合理 |
| **安全性** | 用户健康数据（训练、心率等）加密存储，遵守相关隐私法规 |
| **可扩展性** | AI 人设系统需支持持续演化，社交模块需支持 AI 自主活动扩展 |
| **可靠性** | 跑步记录不可丢失，需离线缓存和断点续传 |
| **用户体验** | 强调陪伴感和专业性平衡，AI 对话需自然且符合跑步场景 |

## 8. 风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| **手表 API 限制** | 部分平台 API 权限严格或历史数据获取受限 | 优先聚焦 Coros，逐步适配其他平台，必要时支持手动导入数据 |
| **AI 人设一致性** | AI 人设演化过快或偏离用户预期影响体验 | 建立人设演化规则和约束，定期校准并允许用户微调 |
| **训练安全性** | 根据用户伤病史生成不当训练计划可能造成伤害 | 强调伤病史收集，加入安全边界（低强度起步、恢复建议），必要时建议就医，且需有免责声明 |
| **AI 社交真实性** | AI 自动发动态和互动可能显得生硬或过于营销化 | 注重自然对话风格，避免过度频繁发文，模拟真实跑友交流节奏 |
| **营养建议合规性** | 营养建议涉及健康需谨慎处理 | 建议通用饮食原则而非医疗诊断，标注免责声明，避免极端饮食方案 |

## 9. 里程碑

| 阶段 | 时间规划 | 目标 |
|---|---|---|
| **MVP 阶段** | 第 1-2 个月 | 完成跑步功能、Coros 数据同步、基于用户信息的个性化训练计划生成与执行、基础训练指导 |
| **AI 伙伴阶段** | 第 2-3 个月 | 上线 AI 跑步伙伴（人设演化）、AI 对话、训练复盘功能 |
| **营养与虚拟赛事阶段** | 第 3-4 个月 | 周期性营养建议、AI 陪跑、虚拟赛事基础体验 |
| **社交生态阶段** | 第 4-5 个月 | 跑圈社交（AI 自动发动态、互动、复盘分享）、AI 间自主活动，完善其他手表平台适配 |
| **优化迭代** | 持续 | 根据日活数据优化 AI 人设、训练计划准确性、社交体验，提升用户留存 |

## 附录

- **差异化亮点**：市场上少有产品能将「专业训练」和「真实陪伴」深度结合。AI 跑步助手的核心是「个性化 AI 跑步伙伴」——既是教练也是朋友，能主动关心、复盘、分享，甚至自主演化，营造独特的陪伴体验。
- **首发策略**：聚焦 iOS/Android 双平台，优先打磨 MVP（跑步 + 训练指导），验证日活数据后再逐步扩展营养、虚拟赛事和社交功能。
